# 消息拉取已读撤回与离线自愈

本文描述消息历史拉取、消息反查、标记已读、撤回、删除会话和离线补拉的协作方式。接口定义见 [消息与会话接口](../api/05-消息与会话接口.md)。

## 1. 参与组件

| 组件 | 职责 |
| --- | --- |
| gateway | HTTP 入站和参数绑定。 |
| msg | 历史消息、已读位点、撤回、会话设置。 |
| connect | 实时下行与 ACK。 |
| message-push | 负责已读/撤回等事件的在线同步。 |
| 前端客户端 | 本地消息列表、未读红点和缺口补拉。 |

## 2. 历史消息拉取

入口：`GET /api/v1/auth/messages/pull`

关键参数：

| 参数 | 说明 |
| --- | --- |
| `convId` | 会话 ID。 |
| `anchorSeq` | 拉取锚点。 |
| `limit` | 单次拉取数量。 |
| `direction` | 0/1 向后，2 向前。 |

拉取语义：

| `direction` | 结果 |
| --- | --- |
| `0` 或 `1` | 返回 `seq > anchorSeq` 的消息，适合追新。 |
| `2` | 返回 `seq < anchorSeq` 的消息，适合加载更早历史。 |

返回字段：

- `messages`：按 seq 升序返回；
- `hasMore`：是否还有更多；
- `maxSeq`：当前会话最大 seq。

## 3. 离线与缺口自愈

WebSocket 不能保证客户端永不掉线，因此必须依赖 HTTP 补拉。

### 3.1 典型补拉场景

| 场景 | 动作 |
| --- | --- |
| 首次打开会话 | 拉最近历史消息。 |
| WebSocket 重连成功 | 从本地最后一个连续 seq 之后补拉。 |
| 收到新消息发现 seq gap | 立即补拉缺口范围。 |
| 在线期间 message-push 投递失败 | 后续进入会话时补拉。 |

### 3.2 删除会话后的拉取语义

删除会话会记录 `clear_seq`。后续 `PullMessages` 时，服务端会过滤掉删除前的旧消息，避免“删除后旧消息又出现”。

## 4. 批量消息反查

入口：`POST /api/v1/auth/messages/get-by-ids`

适用场景：

1. 用户点击回复卡片，需要回查原消息；
2. 本地只缓存了部分消息，需要补详情；
3. 由通知或其他上下文跳转到某条具体消息。

设计注意：

- 未查到的消息不会报错，只会在返回列表中缺失；
- 前端不能假设返回顺序与请求顺序完全一致。

## 5. 标记已读链路

入口：`POST /api/v1/auth/conversations/mark-read`

关键字段：

| 字段 | 说明 |
| --- | --- |
| `convId` | 会话 ID。 |
| `readSeq` | 当前设备已读到的最大连续 seq。 |

处理步骤：

1. msg 将 `read_seq` 更新为 `max(old, req.read_seq)`；
2. 重新计算未读数；
3. 生成 `MSG_MARK_READ` 同步当前账号其他设备；
4. 若是单聊，额外生成 `MSG_READ_RECEIPT` 通知对端已读。

返回的 `unreadCount` 可能仍大于 0，因为标记期间可能有新消息并发写入。

## 6. 撤回链路

入口：`POST /api/v1/auth/messages/recall`

关键字段：

| 字段 | 说明 |
| --- | --- |
| `convId` | 会话 ID。 |
| `msgId` | 待撤回消息 ID。 |

处理步骤：

1. msg 校验消息存在；
2. 校验撤回权限与撤回窗口；
3. 将消息状态更新为撤回；
4. 将 `content` 改写为系统提示内容；
5. 生产 `MSG_RECALL` 下行通知。

撤回后前端渲染应优先看 `status=1`，不要继续展示原始内容。

## 7. 会话列表增量同步

入口：`GET /api/v1/auth/conversations`

关键参数：

| 参数 | 说明 |
| --- | --- |
| `updatedSince` | 增量起点，0 表示全量。 |
| `pageSize` | 单页数量。 |
| `cursor` | 分页游标。 |

典型用途：

1. 应用启动时拉会话列表；
2. 从后台回前台时同步最新未读与最后消息；
3. 撤回、已读、置顶、免打扰变更后刷新会话视图。

## 8. 删除会话与设置更新

### 8.1 删除会话

入口：`DELETE /api/v1/auth/conversations/:convId`

语义：

- 只影响当前用户视角；
- 不是删除消息事实；
- 后续新消息仍可重新激活会话。

### 8.2 更新会话设置

入口：`PATCH /api/v1/auth/conversations/settings`

支持字段：

| 字段 | 说明 |
| --- | --- |
| `mute` | 免打扰。 |
| `pin` | 置顶。 |

未传字段保持不变，前端不应使用默认值覆盖未修改字段。

## 9. 前端推荐策略

1. 本地维护“每个会话最后连续 seq”，而不是只记最后看到的最大 seq。
2. 收到 `MSG_PUSH` 且发现缺口时，优先补拉再做 ACK，避免 ACK 越过缺口。
3. 已读、撤回成功后可以乐观更新 UI，但仍要接受 WebSocket 异步通知再次校正。
4. 会话删除后若收到新消息，不应报错，应把会话重新展示出来。
5. 回复消息、撤回消息、已读回执的渲染逻辑都要能在“先收到实时通知、后补拉历史”的顺序下保持一致。
