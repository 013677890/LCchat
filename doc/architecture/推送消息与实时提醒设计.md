# 推送消息与实时提醒设计

本文描述 LCChat 当前“消息下行推送”和“非消息类实时提醒”两条链路的统一设计、协议边界、已完成项与未完成项。代码事实优先，文档仅总结当前实现与待补工作。

## 1. 目标

LCChat 当前需要支持两类实时下行：

1. 消息类下行：新消息、撤回、已读同步、已读回执。
2. 非消息类实时提醒：好友申请、好友关系变化、群申请审批、群成员/禁言/群状态变化。

统一目标：

- 上游业务服务只负责产生事实事件，不直接维护连接。
- Kafka 负责解耦业务写入与实时投递。
- `message-push` 负责查路由、扩散、调用 `connect`。
- `connect` 负责 WebSocket 最后一公里投递。
- WebSocket 外层统一使用 `connect.MessageEnvelope`。

## 2. 两条链路的职责拆分

| 链路 | 上游生产方 | Kafka Topic | 消费方 | 下行外壳 |
| --- | --- | --- | --- | --- |
| 消息类下行 | `msg` | `msg.push` | `message-push` | `connect.MessageEnvelope` |
| 非消息类实时提醒 | `relation`、`group` 等 | `realtime.push` | `message-push` | `connect.MessageEnvelope` |

## 3. 当前协议设计

### 3.1 消息类下行

已有正式 Proto 契约：

- `proto/msg/msg_push_event.proto`
- `proto/msg/msg_common.proto`
- `proto/connect/connect.proto`

设计方式：

1. `msg` 生成 `MsgPushEvent` 写入 `msg.push`。
2. `message-push` 消费后按会话类型扩散。
3. 最终封装为 `connect.MessageEnvelope`，通过 gRPC 调 `connect`。
4. `connect` 原样透传到 WebSocket Binary Protobuf 帧。

### 3.2 非消息类实时提醒

当前正在向正式 Proto 契约迁移。

新增契约：

- `proto/realtime/realtime_event.proto`
- 生成目标：`pkg/realtimepb`

设计方式：

1. 业务服务生成 `RealtimePushEvent` 写入 `realtime.push`。
2. `message-push` 消费后按 `target.kind` 解析投递目标。
3. 最终同样封装为 `connect.MessageEnvelope`。
4. WebSocket 外层不再区分消息类与提醒类，统一由 `type + data` 路由。

## 4. 关键设计原则

### 4.1 统一下行外壳，不重复造协议

`connect.MessageEnvelope` 是唯一 WebSocket 二进制外层包：

- `type`
- `data`
- `seq`
- `server_ts`
- `trace_id`
- `ack_required`

这样可以保证：

- connect 保持管道职责，不理解业务 payload。
- 客户端只需要维护一个外层协议。
- 业务类型扩展时只新增 payload proto，不必改 connect 主协议。

### 4.2 Kafka 事件与 WebSocket 外壳分层

Kafka 中的事件是“服务间异步事件契约”；
WebSocket 中的 `MessageEnvelope` 是“客户端下行统一外壳”。

二者可以复用 `type/data/trace_id/server_ts/seq` 这些元信息，但语义仍是分层的：

- Kafka 负责跨服务传递。
- connect 负责最终设备投递。

### 4.3 非消息提醒也统一改为 Proto

迁移后的目标是：

- `msg.push`：Proto
- `realtime.push`：Proto
- `connect -> WebSocket`：外层 Proto

这样“业务服务 -> Kafka -> message-push -> connect -> WebSocket”整条主路径都基于 Proto 表达。

## 5. 当前已经做完的部分

### 5.1 connect 主协议已收口为 Binary Protobuf

已完成：

- 删除旧 JSON/Text Frame 兼容代码。
- WebSocket 主协议只保留 `connect.MessageEnvelope`。
- 相关文档已同步说明 connect 仅保留 Binary Protobuf 主路径。

### 5.2 message 类下行链路已完整工作

已完成：

- `msg` 生产 `MsgPushEvent`。
- `message-push` 消费 `msg.push`。
- `message-push -> connect` 通过 gRPC 下发。
- `connect` 通过 WebSocket Binary Protobuf 投递。

## 7. 迁移完成后的预期状态

目标完成后，推送设计将统一为：

```text
relation/group/msg
  -> Kafka(proto event)
  -> message-push(proto decode + route fanout)
  -> connect gRPC(MessageEnvelope)
  -> WebSocket Binary Protobuf
```

其中：

- 消息类下行继续走 `msg.push`
- 非消息类提醒走 `realtime.push`
- 客户端统一按 `MessageEnvelope.type` 路由业务 payload

## 8. 当前结论

当前 LCChat 的推送设计方向已经明确：

- connect 只做最终投递，不做业务判断。
- message-push 统一承担 Kafka 消费、路由查询、扩散与 connect 调用。
- 消息类与非消息类提醒共用一套 WebSocket 外层协议。
- 非消息类提醒正在从“JSON 事件”迁移为“Proto 事件”，但尚未完全收尾。

因此，这项工作当前属于：

- 设计已稳定
- 主链路方向已定
- relation 已基本接通
- group / realtime proto / 文档 / 测试仍在收尾阶段
