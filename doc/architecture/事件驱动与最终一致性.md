# 事件驱动与最终一致性

LCChat 使用 Kafka 解耦跨服务副作用，使用 Outbox（事务外盒）保证部分关键事件和本地数据库事务一致提交。

## 事件来源类型

| 类型 | 代表事件 | 机制 | 适用场景 |
| --- | --- | --- | --- |
| CDC Outbox | `user_created`、`account.deleted`、`group.cache`、`msg.push` | 业务事务内写 `outbox_events`，Debezium 路由到 Kafka | 需要和本地写库强绑定的领域事实。 |
| 直接 Producer | `profile_display_changed`、`realtime.push`、`auth.redis.invalidate`、`user.redis.invalidate`、`relation.redis.invalidate` | 服务直接写 Kafka | 写库事实已成立，后续副作用可降级。 |

## Outbox 表模型

`pkg/outbox` 定义当前 CDC Outbox 模型：

| 字段 | 说明 |
| --- | --- |
| `event_type` | 路由到 Kafka 的事件类型，Debezium EventRouter 使用该字段决定 Topic。 |
| `entity_id` | 事件分区键，例如 `group_uuid`，用于保证同实体有序。 |
| `payload` | JSON 事件负载。 |
| `created_at` | 事件创建时间。 |

当前 Outbox 不维护 pending、processing、failed 状态，可靠投递由 MySQL Binlog、Debezium、Kafka Connect 和 Kafka 共同承担。

## CDC 链路

1. 业务服务在同一 MySQL 事务中写业务表和 `outbox_events`。
2. MySQL binlog 记录事务提交事实。
3. Debezium MySQL Connector 捕获 `outbox_events`。
4. EventRouter 按 `event_type` 路由到同名 Kafka Topic。
5. 消费端用事件内的业务 `event_id` 或幂等表去重。

连接器配置由 [scripts/cdc/register_outbox_connector.sh](../../scripts/cdc/register_outbox_connector.sh) 注册，核心路由规则是 `route.by.field=event_type` 和 `route.topic.replacement=${routedByValue}`。

## Topic 总览

| Topic | 生产方 | 消费方 | 失败语义 |
| --- | --- | --- | --- |
| `user_created` | auth Outbox | user | 资料初始化可重试，消费端幂等。 |
| `profile_display_changed` | user Producer | auth | 登录展示冗余最终同步。 |
| `account.deleted` | auth Outbox | user、relation、group 等 | 下游最终清理，需关注消费延迟。 |
| `group.cache` | group Outbox | group Redis projector、msg membership projector | 两个独立消费组各自投影；非法消息或版本缺口落各自 `dead_events`。 |
| `msg.push` | msg Outbox | message-push | 下行失败短重试后让出 offset，客户端拉取自愈。 |
| `auth.redis.invalidate` | auth | auth Redis invalidation consumer | 只重试不会写回旧值的安全 `DEL`；失败落 auth `dead_events`。 |
| `user.redis.invalidate` | user | user Redis invalidation consumer | 只重试不会写回旧值的安全 `DEL`；失败落 user `dead_events`。 |
| `relation.redis.invalidate` | relation | relation Redis invalidation consumer | go-redis 短重试后补偿好友、黑名单、申请与未读缓存的安全 `DEL`；失败落 relation `dead_events`。 |

## 幂等消费

- `pkg/outbox` 提供 `idempotent_events` 表，唯一约束为 `(event_type, event_id)`。
- `msg.push` 的 message-push 下行是例外：不写 `idempotent_events`，允许 Kafka 至少一次重复，由客户端持久化后按 `conv_id + seq` 合并并抑制重复副作用。
- group cache projector 使用 `group.cache:group-cache-projector` 作为幂等类型前缀。
- msg membership projector 使用 `group.cache:msg-membership-projector`，并把成员更新、单群版本推进和幂等标记放在同一个 MySQL 事务。
- 通用手动提交 Consumer 支持 `kafka.Permanent`：无法解析、schema 不受支持或字段非法时首轮写 `dead_events`，死信落地成功后才提交，禁止用 `nil` 静默跳过。
- handler 或死信成功后的 offset 提交若短暂失败，Consumer 停留在当前消息并只重试提交，不重复执行业务副作用或重复写死信。
- Redis 缓存失效补偿按服务拆分 Topic/Group；auth、user、relation 只删除各自所属缓存，账号注销由 `account.deleted` 驱动下游自行清理。

## 非阻断策略

| 场景 | 主事实 | 非阻断副作用 | 自愈方式 |
| --- | --- | --- | --- |
| 发送消息 | `message` 与 `msg.push` Outbox 已同事务落库 | 会话热数据更新、CDC/在线下行 | 客户端单会话 PullMessages 或多会话 BatchSyncMessages。 |
| 撤回消息 | 消息状态已更新 | 撤回通知下行 | 客户端重新拉取消息状态。 |
| 标记已读 | `read_seq` 已更新 | 多端红点同步、已读回执 | 会话列表增量同步。 |
| connect 断连 | 本地连接已移除 | auth 设备状态 RPC | 下一次登录、心跳或状态查询修正。 |
| group 写操作 | 群表事务与严格递增 `cache_version` 已提交 | Redis 缓存投影、msg 成员会话投影 | Redis 由版本 Lua/权威对账修复；msg 按 Kafka 事件严格连续投影。 |

## 监控重点

- Kafka Connect 连接器状态和 task 状态。
- Kafka 消费组 lag，尤其是 `auth-redis-invalidate-group`、`user-redis-invalidate-group`、`relation-redis-invalidate-group`、`group-cache-projector-group`、`msg-group-membership-projector-group` 和 `message-push-consumer-group`。
- `outbox_events` 增长速度和 Debezium 消费是否停滞。
- `idempotent_events` 写入失败和唯一键冲突。
- message-push 的永久跳过、可重试失败、路由命中率和投递失败率。
- `dead_events` 中 `msg-service:group-membership` 的非法事件和版本缺口。
