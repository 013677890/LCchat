# 数据库设计

本文说明 LCChat 当前 MySQL 数据结构和表职责。事实来源为 `config/mysql/001_schema.sql`，业务代码应以模型和迁移脚本为准，本文用于开发、联调和排障时快速定位数据边界。

## 1. 总体约定

| 项 | 约定 |
| --- | --- |
| 数据库 | `chat_server`。 |
| 字符集 | `utf8mb4`。 |
| 排序规则 | `utf8mb4_unicode_ci`。 |
| 时间精度 | 主要使用 `DATETIME(3)`，保留毫秒。 |
| 软删除 | 多数业务表包含 `deleted_at`。 |
| 用户 ID | 业务主键使用 `user_uuid`，当前长度为 `CHAR(20)`。 |
| 群 ID | 群业务主键使用 `group_uuid` / `uuid`，当前长度为 `CHAR(20)`。 |

MySQL 是绝大多数业务事实的权威存储，Redis 仅作为缓存、限流、路由、幂等或短期位点存储。Kafka 事件只能驱动最终一致，不应替代业务表事实。

## 2. 基础事件表

### 2.1 `outbox_events`

CDC Outbox 事件表。业务服务在本地事务内写入事件，Debezium 监听后路由到 Kafka。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT AUTO_INCREMENT | 自增事件 ID，也是 Debezium outbox event id。 |
| `event_type` | VARCHAR(128) | 事件类型，也是 Kafka topic 路由依据。 |
| `entity_id` | VARCHAR(64) | 事件分区键，通常为 `user_uuid`、`group_uuid` 或 `conv_id`。 |
| `payload` | LONGTEXT | JSON 事件负载。 |
| `created_at` | DATETIME(3) | 事件创建时间。 |

关键索引：

| 索引 | 字段 | 用途 |
| --- | --- | --- |
| `PRIMARY` | `id` | CDC 顺序读取。 |
| `idx_outbox_event_type_created` | `event_type`,`created_at` | 按类型和时间排障。 |
| `idx_outbox_entity_id` | `entity_id` | 按实体查询事件。 |

### 2.2 `idempotent_events`

事件幂等消费记录表。消费者处理完成后写入，避免 Kafka 或 CDC 重复投递导致重复投影。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT AUTO_INCREMENT | 自增主键。 |
| `event_type` | VARCHAR(64) | 消费者内定义的事件类型。 |
| `event_id` | VARCHAR(64) | 事件唯一 ID。 |
| `processed_at` | DATETIME(3) | 处理完成时间。 |

唯一约束 `uk_type_event(event_type,event_id)` 是幂等保证的核心。

## 3. 账号与资料表

### 3.1 `user_account`

auth 服务拥有的账号事实表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 自增主键。 |
| `user_uuid` | CHAR(20) | 用户业务 ID。 |
| `email` | VARCHAR(100) | 登录邮箱，唯一。 |
| `telephone` | VARCHAR(20) | 手机号，唯一但可为空。 |
| `password_hash` | CHAR(60) | 密码哈希，不允许明文存储。 |
| `status` | TINYINT | 0 正常，1 注销。 |
| `is_admin` | TINYINT | 0 普通用户，1 管理员。 |
| `login_nickname` | VARCHAR(20) | 登录返回用昵称冗余。 |
| `login_avatar` | VARCHAR(255) | 登录返回用头像冗余。 |
| `last_login_at` | DATETIME(3) | 最近登录时间。 |
| `created_at` / `updated_at` / `deleted_at` | DATETIME(3) | 生命周期时间。 |

关键索引：`uk_user_account_uuid`、`uk_user_account_email`、`uk_user_account_telephone`、`idx_user_account_status`。

### 3.2 `user_profile`

user 服务拥有的用户资料事实表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 自增主键。 |
| `user_uuid` | CHAR(20) | 用户业务 ID，唯一。 |
| `nickname` | VARCHAR(20) | 昵称。 |
| `avatar` | VARCHAR(255) | 头像 URL。 |
| `gender` | TINYINT | 1 男，2 女，3 未知。 |
| `signature` | VARCHAR(100) | 个性签名。 |
| `birthday` | DATE | 生日。 |
| `qrcode_token` | VARCHAR(64) | 当前二维码 token。 |
| `created_at` / `updated_at` | DATETIME(3) | 生命周期时间。 |

资料展示字段变化后，user 会生产 `profile_display_changed`，auth 消费后回写 `login_nickname` 和 `login_avatar`。

## 4. 设备表

### 4.1 `device_sessions`

auth 服务拥有的设备会话表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 自增主键。 |
| `user_uuid` | CHAR(20) | 用户 UUID。 |
| `device_id` | VARCHAR(64) | 设备唯一 ID。 |
| `device_name` | VARCHAR(64) | 设备展示名。 |
| `platform` | VARCHAR(32) | 平台，如 Web、iOS、Android。 |
| `app_version` | VARCHAR(32) | App 版本。 |
| `ip` | VARCHAR(64) | 登录 IP。 |
| `user_agent` | VARCHAR(512) | User-Agent。 |
| `expire_at` | DATETIME(3) | 会话过期时间。 |
| `status` | TINYINT | 设备状态。当前 HTTP DTO：0 在线，1 离线，2 注销，3 被踢出。 |
| `created_at` / `updated_at` / `deleted_at` | DATETIME(3) | 生命周期时间。 |

唯一约束 `uidx_user_device(user_uuid,device_id)` 保证一个用户同一设备只有一条会话事实。

## 5. 关系表

### 5.1 `user_relations`

relation 服务拥有的单向关系表，好友关系由双方各一条记录表示。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 自增主键。 |
| `user_uuid` | CHAR(20) | 当前用户。 |
| `peer_uuid` | CHAR(20) | 对端用户。 |
| `status` | TINYINT | 0 正常，1 拉黑（原先为好友），2 删除，3 拉黑（原先非好友）。 |
| `remark` | VARCHAR(64) | 好友备注。 |
| `source` | VARCHAR(64) | 添加来源。 |
| `group_tag` | VARCHAR(32) | 好友标签。 |
| `blacklisted_at` | DATETIME(3) | 拉黑时间。 |
| `created_at` / `updated_at` / `deleted_at` | DATETIME(3) | 生命周期时间。 |

唯一约束 `uidx_user_peer(user_uuid,peer_uuid)` 保证同一方向关系唯一。

### 5.2 `apply_requests`

好友/加群通用申请表，其中好友申请由 relation 使用，群申请当前另有 `group_join_requests`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `apply_type` | TINYINT | 0 好友，1 加群。 |
| `applicant_uuid` | CHAR(20) | 申请人。 |
| `target_uuid` | CHAR(20) | 目标用户或目标群。 |
| `status` | TINYINT | 0 待处理，1 通过，2 拒绝，3 过期。 |
| `is_read` | TINYINT(1) | 目标用户是否已读。 |
| `reason` | VARCHAR(255) | 申请理由。 |
| `source` | VARCHAR(32) | 来源。 |
| `handle_user_uuid` | CHAR(20) | 处理人。 |
| `handle_remark` | VARCHAR(255) | 处理备注。 |
| `expired_at` | DATETIME(3) | 过期时间。 |

## 6. 群组表

### 6.1 `groups`

group 服务拥有的群资料表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `uuid` | CHAR(20) | 群 UUID，唯一。 |
| `name` | VARCHAR(64) | 群名称。 |
| `notice` | VARCHAR(500) | 群公告。 |
| `member_cnt` | INT | 群人数。 |
| `owner_uuid` | CHAR(20) | 群主 UUID。 |
| `add_mode` | TINYINT | 0 直接入群，1 审核。 |
| `mute_all` | TINYINT(1) | 是否全员禁言。 |
| `avatar` | VARCHAR(255) | 群头像 URL。 |
| `status` | TINYINT | 0 正常，1 禁用，2 解散。 |
| `cache_version` | BIGINT | 群缓存投影严格递增版本；每条 `group.cache` Outbox 事件在同事务内递增一次。 |
| `deleted_at` | DATETIME(3) | 删除/解散时间。 |

`cache_version` 不由客户端写入。Redis projector、读 miss 回填和周期对账统一用它做 Lua 版本栅栏；已有库通过 `scripts/migration/005_group_cache_projection_version.sql` 初始化。

### 6.2 `group_members`

群成员关系表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `group_uuid` | CHAR(20) | 群 UUID。 |
| `user_uuid` | CHAR(20) | 成员用户 UUID。 |
| `role` | TINYINT | 0 成员，1 管理员，2 群主。 |
| `remark` | VARCHAR(64) | 群名片/备注。 |
| `status` | TINYINT | 0 正常，1 退出，2 踢出，3 待审核。 |

| `inviter_uuid` | CHAR(20) | 邀请人 UUID。 |
| `joined_at` | DATETIME(3) | 入群时间。 |

唯一约束 `uidx_group_user(group_uuid,user_uuid)` 保证同一用户在同一群内唯一。

## 7. 消息与会话表

### 7.1 `conversation`

msg 服务拥有的会话表，每个用户视角一条会话记录。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `conv_id` | VARCHAR(128) | 会话 ID。 |
| `type` | TINYINT | 1 单聊，2 群聊。 |
| `owner_uuid` | CHAR(20) | 会话归属用户。 |
| `target_uuid` | CHAR(20) | 单聊为对端，群聊为群 UUID。 |
| `last_msg_id` | CHAR(64) | 最后消息 ID。 |
| `last_msg_at` | DATETIME(3) | 最后消息时间。 |
| `last_msg_preview` | VARCHAR(255) | 最后消息预览 JSON。 |
| `max_seq` | BIGINT | 会话当前最大 seq。 |
| `read_seq` | BIGINT | 当前用户已读最大 seq。 |
| `clear_seq` | BIGINT | 会话清空/删除位点。 |
| `unread_count` | BIGINT | 未读数。 |
| `mute` | TINYINT(1) | 免打扰。 |
| `pin` | TINYINT(1) | 置顶。 |

### 7.2 消息表

schema 中消息表字段用于保存消息事实，HTTP/gRPC 暴露的 `MsgItem` 字段包括 `msg_id`、`client_msg_id`、`conv_id`、`seq`、`from_uuid`、`msg_type`、`content`、`status`、`send_time`、`reply_to_msg_id`、`at_users`。

设计约束：

- `conv_id + seq` 是会话内排序核心。
- `client_msg_id + from_uuid + device_id` 通过 Redis 先做短期幂等，数据库仍保存最终消息事实。
- 撤回只修改消息状态和内容展示，不删除消息行。

## 8. 维护规则

1. 新增表或字段时，必须同步更新本文件、对应服务文档和 API 文档。
2. 任何跨服务读写必须遵守数据所有权，不能为了方便跨库直接查询非本服务权威表。
3. 对高频列表查询新增筛选条件时，必须同步评估索引。
4. Outbox 表结构变更必须同步检查 Debezium EventRouter 配置。
