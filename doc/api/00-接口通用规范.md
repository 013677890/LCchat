# 接口通用规范

本文定义 Gateway HTTP API、gRPC 和 WebSocket 的通用约定。HTTP 路由事实来源是 [apps/gateway/internal/router/router.go](../../apps/gateway/internal/router/router.go)。

## HTTP 基础约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1` |
| 公开接口 | `/api/v1/public/*`，不需要登录态。 |
| 认证接口 | `/api/v1/auth/*`，需要 Bearer Token。 |
| 请求格式 | JSON，上传头像接口使用 multipart form。 |
| 响应格式 | 统一 `code/message/data/trace_id/timestamp`。 |
| 分页参数 | 优先使用 `page`、`pageSize`；部分会话接口使用 `cursor`。 |
| 时间戳 | 业务事件时间多使用 Unix 毫秒；HTTP 响应 `timestamp` 为 Unix 秒。 |

## 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "trace_id": "trace-id",
  "timestamp": 1710000000
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 业务状态码，成功为 `0`。 |
| `message` | 业务状态文案，默认来自 `consts.CodeMessage`。 |
| `data` | 响应数据，无数据时为 `null`。 |
| `trace_id` | 请求链路 ID，用于排障。 |
| `timestamp` | 响应生成时间，Unix 秒。 |

## HTTP 状态码策略

| 场景 | HTTP 状态码 | Body `code` |
| --- | --- | --- |
| 成功 | 200 | `0` |
| 参数、权限、业务失败 | 200 | `10000-29999` |
| 系统内部错误、上游不可用、超时 | 500 | `30000-39999` |

业务方必须读取 body 中的 `code` 判断业务结果，不能只依赖 HTTP 状态码。

## 认证约定

认证接口需要：

```http
Authorization: Bearer <access_token>
```

设备相关链路建议同时携带：

```http
X-Device-ID: <device_id>
```

Gateway 会解析 JWT 并在上下文中写入 `user_uuid`、`device_id`、`trace_id`、`client_ip`。WebSocket 鉴权比 HTTP 更严格，会额外校验 Redis 中的 AccessToken 哈希，详见 [WebSocket协议](06-WebSocket协议.md)。

## 分页约定

普通分页：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，从 1 开始。 |
| `pageSize` | 每页数量，通常上限 100。 |
| `status` | 可选状态过滤，取值以具体接口为准。 |

会话列表使用游标分页：

| 参数 | 说明 |
| --- | --- |
| `updatedSince` | 增量起始时间，0 表示全量。 |
| `pageSize` | 单页数量，默认 50。 |
| `cursor` | 上一页返回的下一页游标。 |

## 错误码分段

| 范围 | 含义 |
| --- | --- |
| `0` | 成功。 |
| `10000-10999` | 通用客户端错误。 |
| `11000-11999` | 用户、账号、验证码、资料错误。 |
| `12000-12999` | 好友关系错误。 |
| `13000-13999` | 消息和会话错误。 |
| `14000-14999` | 群组错误。 |
| `15000-15999` | 设备会话错误。 |
| `16000-16999` | 黑名单错误。 |
| `17000-17999` | Connect/WebSocket 错误。 |
| `30000-39999` | 服务端错误。 |

完整错误码以 [consts/const.go](../../consts/const.go) 为准。

## gRPC 约定

- gRPC 契约以 [proto](../../proto) 为准。
- 请求校验依赖 Protobuf validate 规则和服务端业务校验。
- Gateway DTO 必须通过转换函数转换为 Protobuf 请求，响应也必须转换回 DTO。
- gRPC 业务错误通过 `apperr` 转为 status，Gateway 入站再解析业务码。

## 字段命名

- HTTP JSON 使用下划线或已有 DTO 标签，以当前 DTO 为准。
- Protobuf 字段使用 snake_case。
- Go 标识符使用英文驼峰。

## 安全要求

- 禁止在日志中记录密码、验证码、完整 AccessToken、完整 RefreshToken。
- 邮箱、手机号等个人信息如需日志输出必须脱敏。
- 修改密码、换绑邮箱、注销账号等敏感操作有更严格用户限流。
