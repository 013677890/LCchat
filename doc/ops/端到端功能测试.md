# 端到端功能测试

## 1. 定位与边界

Docker Compose 端到端测试位于 [`tests/e2e`](../../tests/e2e)，使用 Go 标准
`testing` 包和 `e2e` build tag。普通 `go test ./...` 不会编译这些文件；只有显式
添加 `-tags=e2e` 才会纳入测试，且必须设置 `LCCHAT_E2E=1` 才会访问真实环境。

测试从客户端可见入口验证 HTTP、WebSocket 二进制下行、Kafka 实时推送、Redis
在线路由、MySQL 最终状态和 Docker 服务生命周期。已废弃的 WebSocket 客户端上行
业务消息不在覆盖范围内，消息发送统一走 HTTP。

## 2. 运行前提

1. Docker Desktop 可用，仓库根目录的 Compose 服务已经构建并启动；
2. gateway、connect、Redis 和 MySQL 使用默认宿主机端口，或已通过环境变量覆盖；
3. Kafka 的 `realtime.push` 消费组只能由本轮 Compose `message-push` 消费。若本地
   k3s 共享同一 Kafka 和消费组，应先停止 k3s 中的 `message-push`，避免实时事件被
   另一套环境消费；
4. 目标环境允许创建、修改测试数据，并允许短暂重启 Connect、停止和恢复 Redis。

测试账号使用随机后缀隔离，不会全量清空 MySQL 或 Redis，也不会删除其他开发数据。
测试结束后账号及业务记录会保留，便于根据失败日志追查。

## 3. 运行命令

PowerShell：

```powershell
docker compose up -d --build
$env:LCCHAT_E2E = '1'
go test -tags=e2e -count=1 -v ./tests/e2e
```

Bash：

```bash
docker compose up -d --build
LCCHAT_E2E=1 go test -tags=e2e -count=1 -v ./tests/e2e
```

只验证 E2E 代码能够编译，不访问 Docker：

```bash
go test -tags=e2e ./tests/e2e
```

按顶层分组运行，例如只验证 WebSocket 实时事件与 ACK：

```bash
LCCHAT_E2E=1 go test -tags=e2e \
  -run 'TestE2E/WebSocket_实时事件与_ACK' \
  -count=1 -v ./tests/e2e
```

`-count=1` 用于关闭 Go 测试结果缓存，保证每次都访问真实服务。

## 4. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LCCHAT_E2E` | 空 | 必须为 `1` 才执行真实端到端测试。 |
| `LCCHAT_BASE_URL` | `http://127.0.0.1:8080` | Gateway HTTP 地址。 |
| `LCCHAT_CONNECT_HTTP_BASE_URL` | `http://127.0.0.1:8081` | Connect 健康检查地址。 |
| `LCCHAT_CONNECT_WS_BASE_URL` | `ws://127.0.0.1:8081` | Connect WebSocket 地址。 |
| `LCCHAT_CONNECT_WS_ORIGIN` | 空 | 可选 WebSocket `Origin`；空值表示不发送。 |
| `LCCHAT_REDIS_ADDR` | `127.0.0.1:16379` | 验证码、ACK 和在线路由使用的 Redis。 |
| `LCCHAT_MYSQL_DSN` | `root:root@tcp(127.0.0.1:13306)/chat_server?parseTime=true&multiStatements=true` | 直接校验或构造边界数据的 MySQL DSN。 |
| `LCCHAT_REQUEST_TIMEOUT` | `10s` | 单次 HTTP 请求超时，使用 Go duration 格式。 |
| `LCCHAT_EVENT_TIMEOUT` | `12s` | 等待单个 WebSocket 实时事件的超时。 |
| `LCCHAT_HEALTH_TIMEOUT` | `60s` | 等待 Gateway、Connect 恢复健康的总超时。 |
| `LCCHAT_ROOT` | 自动推导仓库根目录 | 执行 Docker Compose 命令的目录。 |
| `COMPOSE_PROJECT_NAME` | 空 | Compose 使用非默认 project name 时设置。 |

## 5. 覆盖范围

| 文件 | 主要能力 |
| --- | --- |
| `auth_test.go` | 登录、验证码、重复注册、Token/设备边界、密码和邮箱修改、二维码、头像异常输入。 |
| `friend_test.go` | 好友申请拒绝/重复、自申请、不存在用户、备注和标签清空、黑名单阻断。 |
| `message_test.go` | `clientMsgId` 幂等、多消息类型、非法内容、分页、离线拉取、`sync-batch`、撤回边界。 |
| `group_test.go` | 入群申请、直接入群、重复审核、角色权限、成员/全员禁言、移除成员、解散后操作。 |
| `websocket_events_test.go` | 心跳、消息/已读/好友/群组全部实时事件，以及 ACK 大小写、重复、乱序、越界和跨会话。 |
| `websocket_lifecycle_test.go` | 同设备替换、多设备在线、路由 TTL、断线清理、Connect 重启恢复、Redis 不可用 ACK。 |

测试入口 [`e2e_test.go`](../../tests/e2e/e2e_test.go) 按上述依赖顺序串行执行，
禁止把顶层分组改为并行，否则好友关系、群成员状态、消息 seq 和在线路由会相互污染。

## 6. 数据与服务变更

- 每轮创建 A、B、C、D 四个随机测试账号，并为多个设备签发真实 Token；
- 直接向 Redis 写入测试验证码和路由边界数据；
- 超时验证码、过期二维码和超时撤回会构造对应的 Redis/MySQL 状态；
- Connect 生命周期测试会执行 `docker compose restart connect`；
- Redis 故障 ACK 测试会停止 Redis，并通过测试清理逻辑重新启动；
- 若测试进程被强制终止，应执行 `docker compose up -d redis connect` 恢复服务。

## 7. 当前 Docker 基线

截至 2026-08-01，普通测试 `go test ./...` 全部通过；消息与会话、群组权限、
WebSocket 实时事件、ACK、Redis 故障响应及 Connect 重启恢复均已通过真实 Docker
验证。完整 E2E 仍会因以下当前业务行为返回失败：

1. logout 后旧 AccessToken 仍可访问 HTTP 接口；
2. 踢出设备后该设备旧 AccessToken 仍可访问 HTTP 接口；
3. AccessToken 与请求头 `device_id` 不匹配时仍可访问；
4. 可以向不存在的用户提交好友申请；
5. 空字符串不能清空好友备注和标签；
6. Redis 在线路由 key 过期后，已有连接的心跳不会重新创建路由。

这些是测试暴露的业务缺陷，不是测试框架跳过或环境未启动。修复对应业务代码后，
应删除本节已解决项并重新运行完整套件。
