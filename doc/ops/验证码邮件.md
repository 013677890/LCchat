# 验证码邮件

本文说明当前项目验证码邮件发送能力的用途、依赖配置、常见错误和联调注意事项。事实来源为 `deploy/env/chatserver.env.example` 与 auth 服务职责。

## 1. 用途

当前验证码邮件主要用于以下业务：

| type | 场景 |
| --- | --- |
| `1` | 注册。 |
| `2` | 验证码登录。 |
| `3` | 重置密码。 |
| `4` | 换绑邮箱。 |

统一入口：

- `POST /api/v1/public/user/send-verify-code`

## 2. 关键配置

| 变量 | 说明 |
| --- | --- |
| `EMAIL_SENDER` | 发件邮箱。 |
| `EMAIL_SENDER_NAME` | 发件人名称。 |
| `EMAIL_SMTP_HOST` | SMTP 服务器地址。 |
| `EMAIL_SMTP_PORT` | SMTP 端口。 |
| `EMAIL_AUTH_CODE` | SMTP 授权码，不是邮箱登录密码。 |

模板中默认示例为 QQ 邮箱：

| 变量 | 默认示例 |
| --- | --- |
| `EMAIL_SMTP_HOST` | `smtp.qq.com` |
| `EMAIL_SMTP_PORT` | `465` |

## 3. 发送链路

1. 前端调用 `send-verify-code` 接口，带上 `email` 和 `type`；
2. gateway 校验 DTO；
3. auth 校验邮箱格式和验证码类型；
4. auth 先做限流，再生成验证码；
5. auth 将验证码写入 Redis；
6. auth 调用 SMTP 发送邮件；
7. 成功返回 `expireSeconds`。

## 4. Redis 与限流

验证码发送受三层控制：

| Key | 含义 |
| --- | --- |
| `user:verify_code:{email}:{type}` | 验证码正文。 |
| `user:verify_code:1m:{email}` | 单邮箱 1 分钟频控。 |
| `user:verify_code:24h:{email}` | 单邮箱 24 小时频控。 |
| `user:verify_code:1h:{ip}` | 单 IP 1 小时频控。 |

这意味着：

1. 同一邮箱短时间重复点击会被拒绝；
2. 同一 IP 大量尝试也会被拦截；
3. 邮件发送成功与否都会影响前端按钮状态设计。

## 5. 前端联调建议

1. 发送按钮应带倒计时，至少 60 秒内不可重复点击；
2. 前端展示的倒计时以接口返回的 `expireSeconds` 为准，但 1 分钟频控仍需单独处理按钮状态；
3. 验证码输入框建议固定 6 位；
4. 注册、登录、重置密码、换绑邮箱应显式区分 `type`，不要复用错误值。

## 6. 常见错误码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `10001` | 参数验证失败 | 检查邮箱格式、type 值。 |
| `10005` | 请求过于频繁 | 按钮禁用并提示稍后重试。 |
| `11005` / `11027` | 邮箱格式错误 | 提示修正邮箱。 |
| `11018` | 验证码类型无效 | 检查 type。 |
| `11028` | 发送验证码过于频繁 | 倒计时并禁止重复发送。 |
| `30001` / `30002` | 服务端或外部服务异常 | 提示稍后再试。 |

## 7. 运维排查点

当“接口成功率低”或“用户收不到邮件”时，按顺序检查：

1. `EMAIL_AUTH_CODE` 是否已替换模板占位值；
2. SMTP Host / Port 是否正确；
3. 发件邮箱是否已开启 SMTP / 授权码；
4. auth 日志是否有 SMTP 连接失败、认证失败；
5. Redis 是否正常写入验证码和限流 Key；
6. 是否因为频控导致业务错误而非真正的 SMTP 故障。

## 8. 安全要求

1. 不能在日志中打印明文验证码；
2. 不能把 `EMAIL_AUTH_CODE` 写进代码、文档示例或提交到仓库；
3. 验证码邮件只用于短期身份验证，不应被当作长期凭证。
