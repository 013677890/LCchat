# 本地运行与手工测试

本文说明 LCChat 在本地使用 Docker Compose 启动依赖与服务的方式，并给出最小手工测试路径。事实来源为 `docker-compose.yml`、`deploy/env/chatserver.env.example` 和各服务健康检查配置。

## 1. 运行目标

本地运行需要覆盖以下能力：

1. MySQL、Redis Stack Server（含 RedisBloom）、Kafka、Kafka Connect、MinIO 基础设施启动；
2. auth、user、relation、group、msg、gateway、connect、message-push 服务启动；
3. Gateway HTTP、Connect WebSocket、各服务 metrics / health 可访问；
4. 至少完成一次注册、登录、资料读取、好友或消息链路的手工联调。

## 2. 启动前准备

### 2.1 环境变量文件

复制环境变量模板：

```powershell
Copy-Item "deploy/env/chatserver.env.example" "deploy/env/chatserver.env"
```

至少检查以下字段：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_DSN` | MySQL 连接串。 |
| `REDIS_ADDR` | Redis 地址。 |
| `KAFKA_BROKERS` | Kafka 地址。 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | MinIO 凭据。 |
| `EMAIL_SENDER` / `EMAIL_AUTH_CODE` | 验证码邮件发送账号。 |
| `CONNECT_ADDR` / `CONNECT_GRPC_ADDR` | Connect HTTP / gRPC 地址。 |

### 2.2 端口预期

本地常用端口：

| 组件 | 端口 |
| --- | --- |
| gateway HTTP | `8080` |
| connect HTTP | `8081` |
| message-push HTTP | `8084` |
| MySQL | `13306 -> 3306` |
| Redis Stack Server | `16379 -> 6379` |
| Kafka | `9092` |
| Kafka Connect | `8083` |
| MinIO API | `9000` |
| MinIO Console | `9001` |

## 3. 启动方式

### 3.1 全量启动

在项目根目录执行：

```powershell
docker compose up --build
```

若只需要后台运行：

```powershell
docker compose up --build -d
```

### 3.2 启动顺序说明

Compose 依赖关系大致如下：

1. `mysql`、`redis`、`kafka`、`kafka-connect`、`minio`
2. `cdc-init` 注册 Debezium outbox connector
3. `auth`、`user`、`relation`、`group`
4. `msg`
5. `gateway`、`connect`
6. `message-push`

其中：

- `auth/user/relation/group` 依赖 `cdc-init` 完成；
- `msg` 依赖 `group`；
- `message-push` 依赖 `group`、`connect`、`redis`、`kafka`。

### 3.3 k3s 联调时只启动基础设施

原生 k3s 联调时，应用服务运行在 `lcchat-dev` 命名空间，Docker Compose 只需要保持基础设施运行：

```powershell
docker compose up -d mysql redis kafka kafka-connect minio
docker compose up --force-recreate cdc-init
```

其中 `cdc-init` 成功注册 Debezium connector 后会退出，这是预期行为。若注册失败，优先检查脚本行尾、Kafka Connect 健康状态和 MySQL `debezium` 账号权限。

### 4.3 基础设施检查

| 组件 | 检查方式 |
| --- | --- |

## 5. 最小手工联调路径

### 5.1 发送验证码

```http
POST http://127.0.0.1:8080/api/v1/public/user/send-verify-code
Content-Type: application/json

{
  "email": "your_email@example.com",
  "type": 1
}
```

若邮件配置正确，应能收到验证码。

### 5.2 注册

```http
POST http://127.0.0.1:8080/api/v1/public/user/register
Content-Type: application/json

{
  "email": "your_email@example.com",
  "password": "12345678",
  "verifyCode": "123456",
  "nickname": "测试用户"
}
```

### 5.3 登录

```http
POST http://127.0.0.1:8080/api/v1/public/user/login
Content-Type: application/json
X-Device-ID: web-local-001

{
  "account": "your_email@example.com",
  "password": "12345678",
  "deviceInfo": {
    "deviceName": "Chrome on Windows",
    "platform": "Web",
    "osVersion": "Windows 11",
    "appVersion": "1.0.0"
  }
}
```

登录成功后保存：

- `accessToken`
- `refreshToken`
- `userInfo.uuid`
- `X-Device-ID`

### 5.4 查询个人资料

```http
GET http://127.0.0.1:8080/api/v1/auth/user/profile
Authorization: Bearer <accessToken>
X-Device-ID: web-local-001
```

### 5.5 建立 WebSocket

```text
ws://127.0.0.1:8081/ws?token=<accessToken>&device_id=web-local-001
```

握手成功后可发送 `heartbeat` 二进制帧测试连通性。

## 6. 推荐联调顺序

按功能递进建议：

1. 注册 / 登录 / 刷新 Token
2. 获取与更新资料
3. 获取二维码 / 搜索用户
4. 好友申请 / 处理申请
5. 建群 / 拉群资料
6. WebSocket 建连
7. 发送消息 / 拉消息 / 标记已读 / 撤回

## 7. Go 端到端功能测试

真实 HTTP、WebSocket、Redis、MySQL 和 Docker 生命周期测试统一位于
[`tests/e2e`](../../tests/e2e)。旧 Python 与 PowerShell 黑盒脚本已经移除。

启动完整 Compose 环境后，在 PowerShell 中执行：

```powershell
docker compose up -d --build
$env:LCCHAT_E2E = '1'
go test -tags=e2e -count=1 -v ./tests/e2e
```

该测试会创建带随机后缀的真实账号和业务数据，并在生命周期用例中重启
`connect`、暂停后恢复 `redis`。请只对允许写入和短暂重启的本地联调环境运行。

完整覆盖范围、配置项、按模块运行命令以及当前已知失败断言见
[端到端功能测试](端到端功能测试.md)。

## 8. 常见问题排查

### 8.1 收不到验证码邮件

检查：

1. `EMAIL_AUTH_CODE` 是否为正确 SMTP 授权码；
2. `EMAIL_SMTP_HOST` / `EMAIL_SMTP_PORT` 是否正确；
3. auth 服务日志是否有 SMTP 错误。

### 8.2 注册成功但资料查不到

这是最终一致窗口问题，检查：

1. MySQL `outbox_events` 是否已写入 `user_created`；
2. Kafka Connect connector 是否为 `RUNNING`；
3. Kafka topic 中是否存在 `user_created`；
4. user 服务消费是否成功；
5. `user_profile` 和 `idempotent_events` 是否已有对应记录。

### 8.3 WebSocket 握手失败

优先检查：

1. `token` 是否过期；
2. `device_id` 是否与登录时一致；
3. Redis `auth:at:{user_uuid}:{device_id}` 是否仍存在；
4. `CONNECT_ALLOWED_ORIGINS` 是否允许当前来源。

### 8.4 消息发送成功但对端没实时收到

检查：

1. 对端是否建立 WebSocket；
2. `msg.push` 是否写入 Kafka；
3. message-push 是否消费成功；
4. Redis 在线路由是否存在；
5. connect 节点是否在线。

## 9. 清理与重置

停止服务：

```powershell
docker compose down
```

连同卷一起清理：

```powershell
docker compose down -v
```

说明：该操作会删除本地 MySQL、Redis、MinIO 数据卷，仅在确认需要重置环境时执行。
