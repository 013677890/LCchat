# 项目总览

LCChat 是一个基于 Go 的即时通信后端，当前代码采用多进程微服务形态。系统通过 Gateway 暴露 HTTP API，通过 gRPC 完成服务间同步调用，通过 Kafka 承载跨服务事件和消息下行异步链路，通过 Redis 承载 Token、缓存、限流、在线路由、消息幂等与 ACK 位点。

## 当前服务清单

| 服务 | 目录 | 主要职责 |
| --- | --- | --- |
| gateway | [apps/gateway](../../apps/gateway) | HTTP API 网关，负责路由、鉴权、限流、超时、日志、指标和 gRPC 聚合。 |
| auth | [apps/auth](../../apps/auth) | 账号认证、注册登录、验证码、Token、设备会话、账号安全与注销。 |
| user | [apps/user](../../apps/user) | 用户资料、头像、二维码、搜索、资料展示字段投影。 |
| relation | [apps/relation](../../apps/relation) | 好友申请、好友关系、黑名单、关系状态。 |
| group | [apps/group](../../apps/group) | 群资料、群成员、角色、禁言、入群申请、群缓存投影。 |
| msg | [apps/msg](../../apps/msg) | 消息落库、会话维护、seq 分配、撤回、拉取、已读、推送事件生产。 |
| connect | [apps/connect](../../apps/connect) | WebSocket 长连接、在线路由、心跳、ACK、内部 gRPC 推送入口。 |
| message-push | [apps/message-push](../../apps/message-push) | 消费 `msg.push`，查在线路由并调用 connect 投递下行消息。 |

## 基础设施

| 组件 | 用途 |
| --- | --- |
| MySQL 8 | 业务数据持久化，包含账号、资料、关系、群组、消息、会话、Outbox 与幂等表。 |
| Redis Stack Server 7.4 | Token、验证码、缓存、限流、在线路由、消息幂等、ACK 位点，以及 RedisBloom 存在性索引。 |
| Kafka | 事件驱动、消息推送异步化、跨服务最终一致。 |
| Kafka Connect + Debezium | 监听 MySQL `outbox_events`，把本地事务内事件路由到 Kafka Topic。 |
| MinIO | 对象存储，当前主要服务头像上传与公开访问。 |
| Prometheus | 通过 `/metrics` 暴露服务指标。 |
| SMTP | 邮箱验证码发送。 |

## 主要能力

- 账号注册、密码登录、验证码登录、刷新 Token、登出、账号注销。
- 用户资料维护、头像上传、二维码名片、用户搜索、批量资料查询。
- 好友申请、好友列表、好友增量同步、备注标签、黑名单。
- 群创建、群资料、成员管理、入群申请、群主转让、角色、禁言。
- 单聊和群聊消息发送、单会话拉取、按多会话独立 seq 位点批量同步、消息撤回、会话列表、已读、免打扰和置顶。
- WebSocket 下行推送、多端同步、设备在线状态、消息 ACK 位点。

## 当前运行形态

本地联调以 [docker-compose.yml](../../docker-compose.yml) 为准。业务服务容器当前通过 `go run ./cmd` 启动，偏开发联调形态；基础设施包括 MySQL、Redis Stack Server、Kafka、Kafka Connect、CDC 初始化、MinIO。环境变量示例见 [deploy/env/chatserver.env.example](../../deploy/env/chatserver.env.example)。

## 一致性原则

- 核心写入先保证本服务数据库事实成立。
- 跨服务副作用优先通过 Kafka、Outbox 或异步任务完成。
- 可自愈链路不阻断主流程，例如消息已落库后 Kafka 投递失败，客户端仍可通过拉取修正状态。
- AccessToken 采用无状态 JWT，HTTP 与 WebSocket 握手都不依赖 Redis；Redis 故障主要影响续期、在线路由和 ACK。
