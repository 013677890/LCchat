# 服务边界

服务边界的核心原则是“谁拥有数据，谁负责写入；其他服务通过 gRPC、事件或缓存投影协作”。禁止为了省一次调用直接跨服务修改非本域数据。

## 边界总表

| 服务 | 数据所有权 | 对外能力 | 禁止事项 |
| --- | --- | --- | --- |
| gateway | 不拥有业务数据 | HTTP 入口、认证上下文、请求治理、聚合转发 | 不写业务表，不实现领域规则。 |
| auth | `user_account`、`device_sessions`、Token、验证码 | 注册登录、Token、设备、账号安全 | 不维护公开用户资料和好友关系。 |
| user | `user_profile` | 资料、头像、二维码、搜索、资料卡片 | 不修改账号凭证，不直接维护关系和群成员。 |
| relation | `user_relations`、好友申请事实 | 好友、黑名单、关系判断 | 不查询或修改账号表，用户展示信息通过资料能力聚合。 |
| group | `groups`、`group_members`、`group_join_requests` | 群资料、群成员、角色、禁言、入群审批 | 不维护消息表，不直接管理 WebSocket 连接。 |
| msg | `message`、`conversation`、`group_conversation` | 消息与会话领域 | 不维护在线连接，不直接操作群成员事实。 |
| connect | 本地连接、Redis 在线路由、ACK 位点 | WebSocket、内部 gRPC 推送、踢线 | 不消费 Kafka，不做业务权限判断。 |
| message-push | 不拥有业务数据 | `msg.push` / `realtime.push` 到 connect 的桥接 | 不落业务库，不做业务判定。 |

## 同步调用边界

| 调用方 | 被调方 | 用途 |
| --- | --- | --- |
| gateway | auth/user/relation/group/msg | HTTP 请求转 gRPC。 |
| connect | auth.DeviceService | 连接建立、断开时异步更新设备状态。 |
| msg | relation/group | 发送前校验好友、黑名单、群成员和群禁言。 |
| message-push | group | 群聊下行扩散和群类实时提醒前查询群成员/管理员。 |
| message-push | connect | 按 Redis 路由调用目标 connect 节点投递消息或实时提醒。 |
| user | auth.InternalAuthService | 资料展示字段变更后回写登录展示冗余字段。 |

## 异步事件边界

| 事件 | 生产方 | 消费方 | 目的 |
| --- | --- | --- | --- |
| `user_created` | auth Outbox | user | 注册成功后初始化用户资料。 |
| `profile_display_changed` | user | auth | 同步登录展示昵称、头像冗余字段。 |
| `account.deleted` | auth Outbox | user/relation/group 等 | 账号注销后的资料、关系、群相关异步清理或投影更新。 |
| `group.cache` | group Outbox | group Redis projector、msg membership projector | 将群写模型最终事实分别投影到 Redis 与 msg 自有会话表。 |
| `msg.push` | msg | message-push | 消息、撤回、已读、回执等下行推送事件。 |
| `realtime.push` | relation/group | message-push | 好友、关系、群申请和群状态等非消息类实时提醒。 |

## 跨界访问规则

- Gateway 可以聚合多个服务结果，但不写业务数据。
- 业务服务之间优先通过 gRPC 查询对方领域能力，不能直接改对方表。
- 高吞吐或最终一致链路优先走 Kafka，不能把下游推送结果绑定到用户主请求。
- Redis 缓存不是权威事实，权威事实仍在对应服务的 MySQL 表。
- Connect 是最后一公里管道，所有业务判断必须在上游完成。

## 账号与用户资料拆分

- auth 拥有账号事实：邮箱、手机号、密码哈希、账号状态、Token、设备会话。
- user 拥有展示资料：昵称、头像、性别、生日、签名、二维码。
- 登录返回的最小用户信息来自 auth 的登录展示冗余字段，冗余字段由 user 资料变更事件回写。

## 群组与消息拆分

- group 拥有群成员、角色、全员禁言、单人禁言等权限事实。
- msg 在发送前调用 group 校验发送权限，消息落库后只维护消息和会话事实。
- message-push 下行群聊时再次查询 group 成员用于在线扩散，但不改变群成员数据。
